## What RC1 adds

1. reviewer-facing `SHOWCASE.md`;
2. one-command Windows and Unix demos;
3. `tools/demo.py`, which talks to the release executable over real MCP STDIO;
4. current Codex MCP setup documentation;
5. `scripts/rc_gate.py`;
6. CI execution of both the RC gate and the reviewer-facing demo;
7. a root README that reflects the actual v1.2 development state.

## RC go/no-go sequence

Run from the repository root.

```bash
python scripts/rc_gate.py
python scripts/static_audit_v12.py
python scripts/lexical_rust_audit.py
python scripts/operation_manifest.py
python scripts/validate_golden_manifest.py
python scripts/validate_full_audit.py

cargo test --locked --all-targets
cargo clippy --locked --all-targets
cargo build --locked --release

python scripts/verify_v12_operations.py
python scripts/verify_statistics.py
python scripts/verify_multiplicity.py

python golden/run_golden.py --exe ./target/release/yekaterina --out ./golden_results/rc1
python scripts/check_golden_result.py ./golden_results/rc1/result.json
python full_audit/run_full_audit.py --exe ./target/release/yekaterina --out ./full_audit_results/rc1 --strict

python tools/demo.py ./target/release/yekaterina
```

On Windows, additionally run:

```powershell
.\DEMO_WINDOWS.bat ".\target\release\yekaterina.exe"
```

## Promotion rule

Promote to the stable distribution only if:

- CI is green on the exact candidate commit;
- the RC gate and static audit have no failures/pending items;
- Golden is 527/527;
- Full Capability Audit is 1,410/1,410;
- all three independent Python verifiers pass;
- the real MCP demo prints `DEMO PASS`;
- the packaged Windows binary passes the same demo;
- release archive hashes are generated and verified.

If an invariant above changes intentionally, stop the RC and record a new
compatibility decision instead of weakening the gate.
